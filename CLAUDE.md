## Project Overview

**Acquisitions API** — A production-grade Express.js TypeScript API for managing user acquisitions with Supabase authentication and PostgreSQL persistence via Drizzle ORM.

**Tech Stack:**
- **Runtime:** Node.js 18+ with ES modules
- **Framework:** Express.js 5.2.1
- **Language:** TypeScript (strict mode)
- **Database:** PostgreSQL (via Supabase) + Drizzle ORM
- **Auth:** Supabase
- **Validation:** Zod
- **Dev Tools:** tsx (TypeScript runner), ESLint, Prettier
- **Container:** Docker (multi-stage build) & Docker Compose

## Architecture

### Directory Structure
```
src/
  ├── app.ts              # Express app setup (middleware, routes)
  ├── server.ts           # HTTP server initialization
  ├── index.ts            # Entry point
  ├── config/
  │   └── postgres.ts     # PostgreSQL connection pool config
  ├── models/
  │   ├── user.model.ts   # Drizzle schema: users table
  │   └── acquisitions.model.ts  # Drizzle schema: acquisitions table
  ├── controllers/        # Route handlers (empty, scaffold)
  ├── routes/             # Route definitions (empty, scaffold)
  ├── middleware/         # Custom middleware (empty, scaffold)
  ├── services/           # Business logic (empty, scaffold)
  ├── utils/              # Utilities (empty, scaffold)
  └── validations/        # Zod schemas (empty, scaffold)

migrations/               # SQL migration files (generated by Drizzle)
drizzle.config.ts        # Drizzle Kit configuration
docker-compose.yml       # Local dev environment (hot-reload)
Dockerfile               # Multi-stage build (dev + production)
```

### Data Model
- **users:** `id`, `name`, `email` (unique), `password`, `role` (default: 'user'), `created_at`, `updated_at`
- **acquisitions:** `id`, `user_id` (FK → users.id), `asset_name`, `acquired_at`

### Entry Point Flow
1. `src/index.ts` loads `.env` config
2. Imports `src/server.ts`
3. `src/server.ts` imports `src/app.ts` (Express app)
4. HTTP server listens on `PORT` (default: 3000)

## TypeScript Configuration

**Key Settings** (tsconfig.json):
- `strict: true` — Full type safety enabled
- `target: ES2022`, `module: ESNext` — Modern JavaScript
- `outDir: ./dist` — Compiled output directory
- `declaration: true` — Generate .d.ts files for packages
- `ts-node.esm: true` — ESM support for tsx/ts-node

**Important:** The project uses ES modules throughout. All imports must include file extensions (`.js`, `.ts`). Example: `import app from './app.js'` (even in TypeScript files, compiled output references .js).

## Database & Migrations

### Drizzle ORM
- Schema defined in `src/models/*.model.ts` using Drizzle API
- Type-safe queries: `db.select().from(users).where(...)`
- Foreign keys: `acquisitions.user_id` references `users.id`

### Migrations
```bash
npm run db:generate   # Generate SQL from schema changes
npm run db:migrate    # Apply pending migrations
npm run db:rollback   # Rollback last migration
```

**Note:** `drizzle.config.ts` expects schema at `./src/db/schema.ts` (currently models are in `./src/models/`). If refactoring to consolidate schemas, update the config path.

**Environment Variables Required:**
```
PGHOST, PGPORT, PGDATABASE, PGUSER, PGPASSWORD
PGSSLMODE=require  (for Supabase)
SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY
```

## Docker

### Multi-Stage Build
1. **dependencies stage:** Production dependencies only
2. **dev-dependencies stage:** Full install (dev + prod)
3. **builder stage:** Compiles TypeScript → JavaScript
4. **production stage:** Runs compiled code from dist/
5. **development stage:** Runs tsx watch for local dev

### Building & Running
```bash
# Development (hot-reload, all deps)
docker build -t acquisitions:dev --target development .
docker run -p 3000:3000 acquisitions:dev

# Production (compiled JS, no dev deps)
docker build -t acquisitions:prod --target production .
docker run -p 3000:3000 acquisitions:prod

# Docker Compose (dev environment)
npm run docker-compose:up
npm run docker-compose:down
```

**Docker Compose** uses the development stage with volume mounts for src/, enabling hot-reload during container development.

`src/controllers/`, `src/routes/`, `src/middleware/`, `src/services/`, `src/utils/`, `src/validations/` are empty. Follow standard patterns when populating:
- **Controllers:** Handle requests/responses
- **Services:** Encapsulate business logic

- **Routes:** Organize endpoints
- **Validations:** Zod schemas for request/response validation

### Dependencies Note
Project uses `npm install --legacy-peer-deps` due to @typescript-eslint peer dependency constraints with ESLint 10. This is expected and safe.

## Common Tasks

**Add a new route:**
1. Create file in `src/routes/` (export Router)
2. Create controller in `src/controllers/` (export handler functions)
3. Import route in `src/app.ts` and register with `app.use()`
4. Run type-check to validate

**Add a database model:**
1. Define schema in `src/models/` using Drizzle API
2. Run `npm run db:generate` to create migration
3. Apply migration with `npm run db:migrate`

**Deploy:**
- Build Docker image targeting production stage
- Run on port 3000 (or set `PORT` env var)
- Ensure `.env` is set with production database credentials
